# Learning from reference sites

When the user says "make it like X", find out which *qualities* they admire, then take those and leave the rest.
Open the site (browser tool or fetch) instead of relying on memory, and write a take/reject table:

| Reference | Take | Reject | Why |
|---|---|---|---|

Copy principles, not pixels or brand assets. Never imitate another product's name, logo or distinctive artwork.

## Patterns from commonly cited references

### X (social timeline)

**Take:**
- A single reading column with divider-separated rows, not floating cards.
- A frosted sticky header; underline tabs.
- An action bar in a fixed order whose icons stay muted until hover.
- 15px body text; pill-shaped controls.
- A near-black neutral canvas.

**Reject:**
- Metric clutter (views, reposts beside likes).
- Hover-only affordances.
- Putting every tool in the sidebar when the mobile layout uses a header. Keep desktop and mobile consistent
  instead.

### Grok (assistant)

**Take:**
- An almost empty screen with one dominant action (a large rounded input).
- White primary buttons on a near-black canvas.
- Very little chrome; large, tight headlines.

**Reject:**
- Its single-purpose layout for a multi-section product. Borrow the hero, not the whole structure.

### PostHog (developer product site)

**Take:**
- A voice with personality: plain, confident, slightly playful copy.
- Documentation-grade structure with an "on this page" outline.
- Empty states that invite rather than apologise.

**Reject:**
- The desktop/operating-system metaphor, the illustration-heavy chrome and the loud accent colours. They suit a
  marketing site, not a daily-use product, and they fight a one-accent rule.

### Reddit (community forum)

**Take:**
- Voting as ranking.
- A recognisable community identity header with an explicit Join state.
- Rules and about in a side rail.

**Reject:**
- Boxed cards in the feed, nested chrome, multiple density modes.

## Writing your own analysis

For each site:
1. Screenshot the home page and one detail page at desktop and phone width.
2. Note the canvas colour, type sizes, corner radii, number of navigation areas, where search and alerts live, how
   the primary action looks, and how empty states read.
3. Fill in the take/reject table, citing a principle for each line.
4. Show the table to the user before applying anything.
